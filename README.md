# 自由画布提取 v1.3.0

将 LibTV、即梦、RHTV、TapNow 自由画布中的提示词、文本引用和素材整理到本地，支持阅读、分类保存、素材下载和离线项目查看。

“打开画布”、平台访问和普通网页共用同一套 Electron 浏览器窗口实现。标签栏直接使用 [adamschwartz/chrome-tabs](https://github.com/adamschwartz/chrome-tabs) 5.4.0 原始组件及其 Draggabilly 2.2.0 依赖，保留原库的外观、尺寸计算和拖动动画；地址栏沿用现有实现，窗口按钮使用系统原生控件。不额外启动或捆绑 Chrome。画布沿用本版本登录会话，与作者选集勾选联动，关闭标签保留作品勾选。作者目录的 `.项目索引.json` 可一次打开全部已保存作品，继续兼容单作品 `.画布项目.json`。来源及适配范围见 [浏览器界面来源](src/browser-toolbar/CHROMIUM-SOURCES.md)。

本次在独立的 `自由画布提取_v1.3` 目录升级，原 `自由画布提取_v1.2` 完整保留。v1.3 暂停独立便携 EXE/ZIP 的构建与发布，保留程序内的轻量模式和全能模式。GitHub 主分支提供当前 v1.3 源码；Releases 中的 v1.0 便携包为历史版本。

## 启动

当前工作目录已经安装依赖。双击 `启动自由画布提取.cmd` 即可构建并启动当前 v1.3 源码；启动入口不会寻找旧便携包。启动脚本优先使用本目录的 `runtime/node.exe`，其次使用 PATH 中的 Node.js，最后尝试本机已有的 Codex 工作区 Node 运行时。构建及启动日志位于 `.runtime/startup.log` 和 `.runtime/startup-error.log`。

新机器需安装 Node.js 22.13 或更高版本（建议 24），在本目录执行 `pnpm install --frozen-lockfile` 和 `pnpm start`。项目固定 Electron、esbuild 和开发检查工具的版本；pnpm 配置只允许 Electron 与 esbuild 的安装脚本。

## 复制与转移

当前依赖使用 `nodeLinker: hoisted` 安装为普通目录，启动器及程序按自身所在位置定位文件。`extendNodePath: false` 避免命令包装脚本保存安装时的绝对路径。完整复制目录后可在新的路径双击 CMD，无需重新安装依赖。

- 同机换目录或换盘：关闭程序后复制整个目录，包含 `node_modules`；不要只复制 CMD 或源码。
- 另一台兼容的 Windows x64 电脑：同时保留 `runtime/node.exe` 和 `node_modules/electron/dist` 中的完整 Electron 运行时，即可直接启动，无需安装 Node.js 或 pnpm，也无需联网下载依赖。当前目录已携带 Node.js 运行时；`runtime` 和 `node_modules` 属于本地运行文件，不进入 Git。
- 只复制源码或从 Git 获取：仍需安装 Node.js 和 pnpm，并执行 `pnpm install --frozen-lockfile`。缺少依赖时不能离线启动。
- 旧副本仍使用 pnpm Junction 链接时：先关闭程序并更新 `pnpm-workspace.yaml`，移除该副本的旧 `node_modules` 目录，再执行一次 `pnpm install --frozen-lockfile`，转为普通目录后再复制。不要复用旧依赖目录，以免保留旧链接和命令包装脚本。

复制时可排除整个 `.runtime`，新目录会自动重建运行资料，但需重新登录平台账号。`.runtime/profile` 保存账号登录资料，分享给他人时应排除；跨电脑复制不会保证平台登录状态继续有效。已保存项目及导出目录的历史路径可能需要重新选择，这与程序能否启动无关。

## 使用

“程序设置 → 网站访问”提供 LibTV、即梦AI、RHTV、TapNow 直达入口，以及小红书、抖音、B站登录入口。下方输入任意网址或关键词，按回车打开独立浏览窗口，关键词使用 Google 搜索。独立窗口不受“显示／隐藏平台”及作品选择联动，登录资料在本机保存并供对应平台读取复用。程序不再定时或在页面加载、焦点变化时监控登录状态。启动时不会自动打开网站。

平台弹窗顶部提供后退、前进、刷新和返回对应平台首页的图标，以及显示当前链接的地址／搜索框。输入网址后按回车打开，输入关键词后按回车进行 Google 搜索，不设发送按钮。网页重定向及画布内跳转会同步更新地址；Ctrl+L 选中地址框，F12 打开或关闭当前网页的开发者工具。读取画布期间导航暂时锁定，地址仍可选中复制，完成后自动恢复。

轻量模式减少在线预览，只使用已有本地预览；全能模式支持在线预览及素材下载。默认项目位置仍是桌面的“自由画布提取”。已保存项目可通过 `.画布项目.json` 或项目文件夹路径打开。

“选择保存位置”会记住上次确认的保存根目录，重启后自动恢复，目录选择窗口也从该位置打开。取消选择不会改变记录；清理浏览器缓存不会清除保存位置。首次使用或位置记录损坏时才使用默认桌面目录。

独立文本节点支持右键或缩略卡片“预览”按钮查看完整正文，阅读区右键也能预览；“下载文本”按节点保存原文为 TXT，在轻量与全能模式下均可使用。素材进度条完成后保持当前主题颜色。

保存提示词、开始下载、阅读区单独下载，以及读取项目后首次打开项目文件夹，都会在项目目录生成或补齐 `作品信息.md`。默认仅读取 LibTV 作者公开资料及作者填写的社交分享链接，保留原始分享文字，不访问外部社交网页或解析其短链接。程序设置中的“访问作者分享的社交主页，补充公开用户资料”默认不勾选，并记忆用户选择；开启后才访问小红书、抖音、B站主页，补充各平台独立的昵称、账号、简介与可读取的统计。其他网站仅保存链接。更改设置后重新读取作者主页更新资料。

抖音登录弹窗不等于作者资料不可读取：程序会继续读取主页中已经加载的公开作者信息，无需关闭弹窗或登录。页面资源持续加载时也可读取已出现的作者资料；实际未取得的信息标记为未读取，作者分享链接始终保留。

程序设置提供小红书、抖音、B 站登录入口；登录后重新点击“开始读取网页”可更新公开资料。登录、验证或网络限制导致未取得的字段明确显示“未读取”，不阻塞作品提取。已完成的作品数据可以继续复用缓存，作者资料会附加到每部作品的文件和项目记录。旧项目的 TXT 文件保留，新保存或更新输出 Markdown；旧项目未保存的社交字段需要重新读取作者或作品页面后补充。

v1.3 使用自己的 `.runtime/profile`，仅继承 v1.2 的外观与保存位置偏好，不复制登录资料。v1.2 及更早版本保存的 schema 2 项目可以继续打开；旧记录未保存的信息仍需重新读取原画布才能补充。

## v1.3 作者选集

支持 LibTV 作者主页地址，例如 `https://liblib.tv/profile?uuid=作者UUID`。粘贴后点击“开始读取网页”才读取作者公开作品列表并展开选集，列表默认全选，此时不读取画布。调整选集后点击右侧“开始读取画布（N）”，读取期间该按钮可停止任务。具体作品链接仍直接读取画布。选择变化不会启动新的画布读取；已完成的数据继续复用。

- 点击整张作品卡片可多选；白色为未选，浅蓝色为已选，底部显示选择状态。支持“全部选中”“清空选择”。
- 搜索框与“展开作品／展开看板”按钮组各占右侧的一半；两个展开按钮可以同时开启或分别关闭，开启时浅蓝色。收起不改变选择。
- 作品与资产共用缩放滑杆和卡片尺寸。作品独立成行，例如每行 8 张、有 10 部作品时先显示 8＋2，资产另起新行。最右端同时切换为文字索引。
- 选择变化会同步更新统计、提示词、资产与阅读区；多选时不按作品分组，阅读区显示所属作品。搜索和类型筛选只影响内容，不隐藏作者选集。
- “保存提示词（N）”和“下载所选作品（N）”中的 N 表示所选作品数；勾选的类型控制保存或下载内容，“按类型分类保存”默认勾选。读取失败需重试或取消选择该作品，避免静默漏存。
- 文件保存为“保存位置／liblib_作者名／作品名／”，提示词、作品信息和项目记录按作品保存。作者或作品同名时追加标识，避免覆盖。
- 下载开始时固定作品及素材类型范围，之后可切换预览选择；下载进度注明本次任务数量，不随预览改变。每个作品目录均保留所需素材。
- 作者主页支持 LibTV、TapNow（`/creator/profile/<作者ID>`）和即梦（`/ai-tool/personal/<作者ID>` 或 `/s/<分享码>/`）；RHTV 暂不支持作者主页批量读取。即梦分享链接跳转后按完整主页处理，自动切换并确认“AI短片”栏目，优先从主页已加载数据批量读取作品、视频地址和画布公开状态，仅对数据缺失项补查详情。作品列表以当前页面实际返回内容为准，未登录时平台可能返回空列表；输入区会显示说明，需要登录时可使用设置中的即梦网站入口。
- 作者作品读取共用一个多标签平台窗口，沿用各平台登录会话，保留拖动排序。取消选择时收起标签，重新选择恢复原页面与排序，不重复加载；读取期间暂时限制标签导航，停止读取仍在主界面操作。
- 作品卡片同步显示“画布已公开／画布未公开／画布状态待确认”。LibTV 使用官网的快照状态判断是否公开，即梦读取主页已加载的作品模型及关联画布状态；明确未公开的作品不会进入画布提取队列，列表完成后即可下载已取得的视频。状态待确认时保留正常读取流程，不将缺失字段直接当作未公开。
- 四个平台的“打开画布”按各自规则进入公开制作过程，并使用各自登录会话。画布未公开的作品继续保留在选集中并注明状态，仅下载该作品发布的视频；登录、网络失败保留为可重试错误。
- 所有提取、下载和文件夹按作品 ID 独立处理；同名作品或共用同一画布的不同作品不会合并，分别提取、分别下载。旧 LibTV 本地项目仍兼容。
- 平台显示首次默认开启，开关状态会保存并在下次启动时恢复。隐藏使用系统透明度，网页保持打开；已读取的每部作品保留独立页面，显示时只呈现当前选集，取消选择立即透明化对应页面。
- 已完成的作品在本次运行内复用内存和磁盘缓存，取消选择后重新选中不会重复提取。磁盘缓存位于当前保存位置的 `.自由画布缓存／本次运行标识／`，更换保存位置后使用新位置；正常退出会清理本次运行创建的缓存，保留用户保存的作品文件。

## 图片信息

项目资产搜索框输入 `mj` 或 `Midjourney`（忽略大小写与首尾空格），仅显示已识别为 Midjourney 的图片；清空恢复原列表。筛选沿用当前素材类别，不根据名称或提示词中提到的 MJ 猜测来源，也不触发下载。

图片、视频、音频、文本共用 44px 阅读区标题栏，展开与收起保持相同布局。已下载的素材及单独保存的 TXT 均在“已下载”右侧提供“定位文件”，不在媒体画面上重复显示保存状态或定位按钮。图片点击查看信息，视频／音频保留原生播放器，文本保留正文复制与纯文本预览。文本下载后按实际文件内容识别保存状态，重新打开仍可定位；文件缺失或正文被外部更改时可重新下载。

阅读区参考缩略图固定为 16:9，只显示素材与编号，左键预览、右键定位文件，悬停预览显示在弹窗上层。展开图标与“所属作品”在同一行，打开独立阅读弹窗，上方参考素材、下方提示词，正文与第一个素材左侧对齐；拖动右下角可调整宽高。顶部两个等宽无文字滑块从左到右分别调整素材尺寸和文字／行内引用小图尺寸，右侧为收缩按钮。字号沿用程序设置的排版比例，弹窗调整不改变全局字号。点击收缩图标或按 Esc 返回原阅读区，保留正文与引用交互。展开、收缩图标使用用户提供的 LibTV 原始 SVG 路径。

阅读区和素材预览中的大图点击均打开图片信息；不再显示独立“图片信息”文字入口或图片上方保存状态。阅读区“定位文件”紧跟“已下载”，展开和收起均保留；素材预览标题栏同样提供“已下载”和“定位文件”。放大镜覆盖图片左上角，图片容器沿用 v1.2 的 16:9 设置，不额外占用工具栏高度。信息弹窗首行左侧文件名、右侧复制提示词／复制全部信息／重新读取／关闭，正文依次展示品牌与模型规格、提示词、生成参数。“更多信息”直接展开 ExifTool 的字段文本；“复制全部信息”复制同一份文本。识别依据可悬停品牌规格行查看。

阅读区自动展示当前已下载图片的 Midjourney 内嵌信息，按文件名与操作栏、规格、提示词、参数、更多信息／打开官网排列；保留复制提示词、复制全部信息与重新读取，阅读区不显示关闭按钮。切换结果图同步更新，下载完成后自动读取；无有效 MJ 信息时保持原有正文展示。画布提示词与图片内嵌信息分别保留。点击图片仍打开原信息弹窗，弹窗保留关闭按钮及原有全部操作。点击当前结果图，查看图片内嵌的模型／品牌、提示词、生成参数及像素尺寸、文件大小、格式；切换结果图后分别读取。识别到有效的 Midjourney Job ID 时，“更多信息”旁显示“打开官网”，使用程序内置浏览器打开该图片的官方作品详情页；两处入口仅文字标签可点击，间隔及行内空白不触发操作。没有有效编号时不显示官网入口，悠船短编号不会拼接为 MJ 地址。没有提示词时不显示缺失提示语，弹窗仅保留文件名操作栏、规格和“更多信息”三行。信息来自原图，尚未下载时可从弹窗下载后重新读取。明确记录与参数特征推测分别标注，C2PA 打开、缩放等处理记录不会被当成原始生成模型。复制提示词保留完整原文，画布提示词保持独立。

下载完成及打开本地作品时，程序后台批量读取已下载图片；每个作品目录的 `.图片信息.json` 保存缓存，未变化的文件直接复用，替换文件后自动失效，支持手动重新读取。PNG 非标准 UTF-8 中文文本兼容解码，保留原始字段与解码记录。普通读取不会修改原图，也不会联网补猜模型或提示词。

内置 ExifTool 13.59 Windows x64 位于 `tools/exiftool/`。完整复制程序时必须包含整个 `tools/`，包括 `exiftool_files/` 及许可证；无需另装 ExifTool、Python 或 Perl，不依赖系统 Path。`pnpm verify:image-info` 验证真实工具与阅读区弹窗，`pnpm verify:transfer` 包含工具复制验证。

## 保留的基础能力

- LibTV、即梦、RHTV、TapNow 拥有独立的读取器、生成参数解析、账号识别、文本规则和素材规则。
- 公共提取服务、媒体访问服务、项目格式校验和 Markdown 导出按职责拆分。
- 新品牌通过适配目录及注册入口接入，账号界面与公共流程无需逐处增加品牌分支。
- 单品牌模块按需加载，失败不会阻止另一个品牌或本地项目访问。
- 保留 `liblib`、`jimeng` 原有内部标识和 schema 2；记录应用版本、适配器版本及完整性状态。
- 任务事件带标识，界面忽略旧任务结果；媒体请求固定绑定所属品牌会话。
- esbuild 处理真实模块依赖，生成物集中在 `build/`；静态检查发现未声明变量及无效引用。
- 自动验证使用合成素材和隔离目录，移除依赖旧私人素材的历史验收入口。

操作说明见 [使用说明](使用说明.md)，账号资料说明见 [账号安全与隐私](账号安全与隐私.md)，开发流程见 [开发说明](开发辅助/开发文档/开发说明.md)，品牌接入约定见 [架构说明](开发辅助/开发文档/架构说明.md)。

测试、验收工具与记录、开发文档和检查配置集中在 [开发辅助](开发辅助/说明.md)。启动、构建和日常运行所需文件保留原位。

RHTV 支持 `https://rhtv.runninghub.cn/projects/canvas/camp/<作品ID>` 作品详情链接，以及 `https://rhtv.runninghub.cn/project/canvas/<画布ID>` 直接画布链接。作品页自动打开“查看创作过程”的只读画布；无需克隆到账号。

RHTV 的“琥珀计划”公开作品已完成真实提取和图片、视频、音频样本下载验证。私人画布需要在程序内登录，Chrome 的登录不会自动共享给程序。平台登录、访问权限及素材链接有效期仍受平台限制。详见 [RHTV 验收记录](开发辅助/验收记录/RHTV-接入验收.md)。

TapNow 支持 `https://app.tapnow.plus/home/taptv/<分类ID>/<作品ID>` 作品详情和 `https://app.tapnow.plus/canvas/<画布ID>` 直接画布链接。作品页自动打开只读创作过程。TapTV 列表页会提示粘贴具体作品链接，不会自动选择列表中的作品。支持当前提示词、模型参数、文本、图片/视频/音频素材及参数引用；上传音频的文件名不会误当生成提示词。详见 [TapNow 验收记录](开发辅助/验收记录/TapNow-接入验收.md)。
